# VisionInspect AI --- Project Specification

## 1. Project Title

**VisionInspect AI: Manufacturing Defect Detection & Quality Inspection
System**

## 2. Project Objective

Build an AI-powered manufacturing quality inspection platform that:

-   Detects product defects from images.
-   Identifies quality issues and anomalies.
-   Classifies defect types.
-   Assesses defect severity.
-   Generates automated quality decisions such as Pass/Fail.
-   Provides inspection reports and manufacturing analytics.
-   Reduces manual inspection effort and improves production quality.

The system should be developed as a centralized platform with image
inspection, computer vision, quality control automation, defect
classification, and manufacturing analytics.

## 3. Dataset

### Primary Dataset

Use the **MVTec AD (MVTec Anomaly Detection) dataset** as the project
dataset.

**Important scope decision:** Do not arbitrarily restrict the project to
only one MVTec AD category unless the project supervisor explicitly
changes the scope. The project should be designed to work with the MVTec
AD dataset and its available categories.

The dataset should be integrated into the project during Week 1--2.

For development, preserve the original MVTec AD organization and
metadata/ground-truth information. Do not modify the original dataset
unnecessarily.

-   Severity scoring
-   Defect size measurement where possible
-   Defect location assessment where possible

### Severity Framework

Use the project specification:

  Parameter                Weight
  ---------------------- --------
  Defect Size                 30%
  Defect Location             25%
  Defect Type                 25%
  Detection Confidence        20%

Formula:

``` text
Severity Score =
(Size × 30%)
+ (Location × 25%)
+ (Defect Type × 25%)
+ (Confidence × 20%)
```

Severity levels:

  Score     Level      Recommended interpretation
  --------- ---------- --------------------------------------------------
  0--39     Low        Minor cosmetic defect; generally acceptable
  40--59    Medium     Moderate concern; inspection review
  60--79    High       Significant issue; repair/rework
  80--100   Critical   Major defect; product rejection/immediate action

If an input required by the severity formula cannot be reliably obtained
from the MVTec AD data/model, do not fabricate a value. Clearly document
the chosen method or limitation.

## 8. Important Implementation Rules for the AI Coding Agent

When implementing this project:

1.  **Follow this document week by week.**
2.  Do not implement later-week features before the current week's
    foundation is working.
3.  Do not skip dataset exploration.
4.  Do not replace MVTec AD with another dataset unless explicitly
    instructed.
5.  Do not arbitrarily restrict the project to a single MVTec AD
    category unless explicitly instructed.
6.  Preserve the original MVTec AD train/test/ground-truth organization.
7.  Do not fabricate defect labels, severity values, or model results.
8.  If a requirement in the architecture is underspecified, make the
    smallest reasonable implementation and document the assumption.
9.  Keep frontend, backend, AI/model, data storage, and configuration
    logically separated.
10. Use environment variables for secrets and configuration.
11. Keep code modular and maintainable.
12. Add basic error handling and input validation.
13. Test each module before moving to the next major module.
14. Maintain a clear README and setup instructions.
15. Use Git commits regularly with meaningful messages.
16. Do not claim a feature is complete unless it is actually implemented
    and tested.
